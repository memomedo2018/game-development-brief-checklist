Unity Rewarded Ads Acceptance Matrix

Specify the placement and reward, then generate a small, testable handover matrix. This worksheet does not connect to an ad network or transmit the entered values.

Acceptance rule

A player receives exactly the agreed reward only after the provider confirms the rewarded view. A tap, ad load, ad open, partial view, or duplicate callback is not proof of completion. Keep the provider event, game transaction, and visible wallet state separately traceable.

The matrix below uses the example values until you generate your own.

Build proof

Record build and source revision, SDK/mediation version, device, OS, test mode, consent state, and placement ID. Remove test credentials from any public evidence.

Ownership

The buyer should control the production network account. Document who can change placement IDs, consent settings, event logging, and reward rules.

Production gate

Confirm network policy, applicable privacy requirements, app-store declarations, and live-mode configuration before launch; the test matrix alone does not certify compliance.
