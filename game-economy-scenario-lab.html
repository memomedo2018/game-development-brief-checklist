INTERACTIVE PLANNING WORKSHEET

Game Economy Scenario Lab

Can a player still afford the required upgrade after an optional purchase? Try one transparent resource path before building the shop, then turn the assumptions into acceptance tests.

The default numbers are illustrative, not ROADFORGE values or industry benchmarks. This arithmetic model is not a balance optimizer, revenue forecast or proof that a mission is playable. No information is sent or saved by this worksheet.

1. Define one route

Verify this assumption in a playable build. Uncheck it if progression blocks the replay or the player cannot complete it.

2. Challenge the assumptions

  • Set the optional purchase to 200. With a 60-coin replay, the arithmetic requires two successful replays for the 120-coin upgrade.
  • Uncheck the replay assumption. The same numerical design becomes a blocked route, not a two-replay recovery plan.
  • Set an optional price above the available coins. Reject that purchase; never create a negative balance.
  • Repeat for a low-success player and a different upgrade order. Record mission duration and consumable spending separately; this small model omits them.

4. Record the acceptance package

Attach the configuration version, build revision, initial save, route, expected and observed balances, result, owner and evidence location. A passed calculation does not establish secure storage, correct receipts, server authority or good player experience.
