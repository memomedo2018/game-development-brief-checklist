Keep the record identity explicit

The example accepts only an agreed seven-field record: event_id, event_name, schema_version, environment, build_id, order_id and cost. The identity used for counting includes environment and build, so a production event cannot silently satisfy a test expectation. A repeated identifier is reported even if a larger expected count might otherwise hide it. Extra fields are rejected; that is a narrow schema rule, not a general privacy certification.

import { reviewEvents } from './event-review-matrix.mjs';
const expected = [{
  environment: 'test', build_id: 'fixture-r1',
  order_id: 'order-1', event_name: 'order_committed', count: 1
}];
const observed = [{
  event_id: 'synthetic-e1', event_name: 'order_committed',
  schema_version: 1, environment: 'test', build_id: 'fixture-r1',
  order_id: 'order-1', cost: 2
}];
console.log(reviewEvents(expected, observed));

With both JavaScript files in the same directory, run node event-review-matrix.test.mjs. No installation, account, API key, network or production connection is needed. Twelve synthetic assertions were run for this resource; they check the reviewer, not a game build.

Interpret the result narrowly

matches_declared_fixture means only that the supplied records meet the declared shape and counts. A fabricated or incomplete capture can still match. The reviewer cannot establish that an SDK emitted the records, that a server received them, that consent was respected, that gameplay committed correctly or that a dashboard processed them.

The cost field is validated as a nonnegative integer; the expected matrix does not verify the amount against gameplay state. If value reconciliation matters, add a separately approved before/after evidence check. Likewise, duplicate checks operate only within the supplied array and event IDs; they do not provide durable deduplication across independent batches.

Give the reviewer a named build and scenario, record the event capture method, and inspect test versus production destinations independently. Never paste personal information, credentials or real player traces into a public issue or example.
