Unity Game Analytics Acceptance Checklist

Use this checklist to turn “analytics installed” into evidence that the game records valid, privacy-aware events in the correct environment and that the buyer can operate the system after handover.

1. Product questions

  • Every event supports a named product decision.
  • Each metric has a population, time window, numerator, denominator, and exclusions.
  • The first event set is limited to decisions the team will actually review.

2. Event contract

  • Names, triggers, parameters, types, allowed values, and examples are documented.
  • Identity and session behavior is defined across restart, offline play, and sign-in.
  • Schema and implementation versions are traceable to a build.

3. Environments

  • Development and production data are isolated.
  • The active environment is visible in build configuration or diagnostics.
  • Cached events and environment switching have a test route.

4. Consent and privacy

  • Collection behavior is defined for granted, denied, revoked, and offline states.
  • Event parameters exclude unjustified personal or sensitive data.
  • Deletion and opt-out routes are tested for the selected SDK version.

5. Build validation

  • Each event has a named build, device, route, expected payload, and count.
  • Valid, invalid, duplicate, retry, and offline cases are recorded.
  • Evidence includes build revision, environment, identity state, and event health.

6. Dashboards

  • Reports answer the original questions and document filters and formulas.
  • Test builds and internal traffic are excluded where required.
  • Dashboard and data-quality owners are named.

7. Access and ownership

  • The buyer controls the production organization, project, billing, and final roles.
  • The delivery team receives least-privilege access.
  • Credential, role, and revocation boundaries are documented.

8. Handover

  • Deliver the event dictionary, code, package versions, environments, tests, and known limits.
  • Include dashboards or query definitions, metric glossary, and data-access notes.
  • Another authorized developer reproduces one route before final acceptance.
