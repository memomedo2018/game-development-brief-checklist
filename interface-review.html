The field kept its name. Its meaning may still have changed.

Two teams can agree on a message called RewardGranted and still disagree about what its amount contains. Review changes to the shared interface before merging a work package, then review the affected consumers. A successful text merge does not answer either question.

This is a small, synthetic JSON-descriptor tool. It does not read C# code, inspect a Unity build, validate payment receipts or decide whether a change is compatible. The examples are invented. No customer data or credentials are involved.

A change that deserves a named reviewer

The baseline says amount is a required number. The candidate calls it a required string and adds an optional receiptId. The new field may be harmless to one consumer and rejected by another. The type change may require parsing, new validation or a deliberate new interface version. The descriptor alone cannot decide.

Run the exact comparison

Download the dependency-free Node tool, the baseline descriptor and the candidate descriptor into one local folder. No package install or network connection is needed to execute the comparison.

node interface-diff.mjs interface-before.json interface-after.json

The saved example output contains two field changes and acceptance: "not_decided". A removal and addition are reported separately; the tool never guesses that a rename preserves meaning.

{
  "status": "review_required",
  "changes": [
    { "message": "RewardGranted", "field": "amount", "change": "field_changed" },
    { "message": "RewardGranted", "field": "receiptId", "change": "field_added" }
  ],
  "acceptance": "not_decided"
}

This excerpt omits before/after field metadata for readability; the downloadable result includes it. no_descriptor_changes means only that this declared shape did not change. A changed unit, range, event timing or business rule can remain invisible when field types stay the same.

Turn a diff into a review decision

  1. Name the baseline and candidate source revisions. Keep both descriptors with the review.
  2. Identify each producer and consumer affected by the changed message, including saved or queued records if they exist.
  3. Ask the consumer owner what old and new inputs must do. Record an explicit conversion or rejection decision rather than silently coercing strings.
  4. Run the relevant implementation checks on the candidate build. Attach observations; the JSON diff is not that evidence.
  5. Let the named integration owner record accept, revise or defer. A clean diff must never auto-fill acceptance.

What the checks actually cover

Eight synthetic Node tests cover unchanged descriptors, a type change, required/optional drift, additions/removals, renamed messages, ordering and invalid descriptors. Download the test file beside the tool and run:

node --test interface-diff.test.mjs

The descriptor accepts only string, number, boolean, object and array labels. Object and array contents are opaque: nested properties, numeric precision, nullability, defaults and serialization rules are not compared. Duplicate names and unsupported type labels are rejected. Do not paste proprietary interface definitions into a public repository; run the local files on your own machine.
