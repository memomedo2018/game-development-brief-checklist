# Game Development Brief & Acceptance Checklist

A practical, platform-neutral checklist for founders and product teams preparing to commission a game. It turns a broad idea into reviewable decisions, milestone evidence, and a source-handover package.

Use it before requesting estimates, then keep it beside the statement of work throughout production. It is intentionally concise: delete irrelevant sections, mark unknowns openly, and attach evidence rather than filling gaps with guesses.

## What this resource includes

- `GAME_PROJECT_BRIEF.md` — a copyable project brief and milestone-acceptance template.
- `index.html` — a readable web version with the same decision structure.

## How to use it

1. Define the player, core loop, platform, input, camera, online boundary, content scope, and first release goal.
2. Mark every assumption that still needs discovery.
3. Give shortlisted teams the same version of the brief.
4. Compare the evidence each team proposes, not only the estimated feature list.
5. Close each milestone with a build, test route, issue list, decision log, and accepted source revision.
6. Update the brief through written change control when the product decision changes.
